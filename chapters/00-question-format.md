# 第0.5章: 質問フォーマット

> **この章は「読むだけ」でOKです。**
> 課題の提出、フィードバック、質疑応答など、プログラムに関するやり取りの型を決めます。

## 1. 修正の仕方

フィードバックに対して修正した際は、該当のフィードバックコメントを引用し、**どこをどう修正したのか** をしっかり記述してください。

```
例
1. if (name == "takeshi") となっていますが、比較の意図が分かりにくいです。
　→ Kotlin では == で文字列比較できるため、そのままにし、変数名を userName に変えて意図を明確にしました。

2. 不要な変数が残っているようです。
　→ コードの簡潔性を保つために、不要な変数を削除しました。
```

## 2. 質問の仕方

プログラムを進めていく中で、疑問に思ったことやわからないことは何でも質問してください。
ただし、次のような質問は避けましょう。

> 「◯◯◯という機能を実現したいのですが、エラーが出てしまいどうやっても解消できません。どのようにすれば実現できるのでしょうか？」

これは起きた結果だけを報告しているので、回答する側からすると「どんなエラーが出たのか」「どのようなコードを書いたのか」「何を試してダメだったのか」が完全に抜けています。
そのため、これらの情報を得るために何度か質問をやり取りすることになり、お互いに時間を無駄にしてしまいます。

質問するスキルは問題を解決する上でとても重要です。
他人の時間も自分の時間も無駄にしないために、以下の質問フォーマットを活用してください。

## 3. 質問フォーマット

```
１. タイトル
（内容が分かるように重要なキーワードを意識して、1行で簡潔に質問内容を要約する）

２. 目的
（最終的に何をしたいのか、何をするための質問なのか）

３. ゴール
（何ができたら問題を解決できるか明確に整理する）

４. わからないこと・問題発生箇所
（問題が発生した経緯、エラーメッセージを記述する。不具合のスクリーンショットを添付しても良い）

５. 調べたこと・試したこと
（参考にしたサイトのURL、自分で調べたこと、検索ワード、試したことをできるだけ詳しく箇条書きにする）
```

上記をすべて埋めるのが理想ですが、最初は次のような状態に陥ると思います。1〜5 をすべて埋められなくても質問してください。

- 何がエラーメッセージなのか分からない
- そもそも自分が何をしようとしているのかも実のところ分かっていない

## 4. AI に聞くときも同じ型で

このフォーマットは AI に質問するときにもそのまま使えます。
「目的」「エラー全文」「試したこと」を渡すと、AI の回答の精度が大きく上がります。
