## 3. 学習用リポジトリの準備

Git プログラムで作った学習用リポジトリ（または新しく作る Public リポジトリ）を使います。
提出物はユニットごとのフォルダに置きます。

```
（リポジトリ直下）
├── unit1/
│   ├── kotlin-intro/        ← Kotlin Playground の演習（.kt ファイル）
│   └── BusinessCard/        ← Android Studio プロジェクト
├── unit2/
│   ├── kotlin-fundamentals/
│   ├── DiceRoller/
│   └── ArtSpace/
└── ...
```

Android Studio プロジェクトを置くときは、プロジェクトフォルダごとコピーし、**`build/` と `.idea/` は含めない** でください（`.gitignore` に書いておくと安全です）。

## 4. 提出の流れ（毎章共通）

1. 章の「提出物」を完成させる
2. `develop` から `feature/<章のファイル名>` ブランチを作る（ブランチ名は各章の冒頭に書いてあります）
3. 提出物をコミットしてプッシュし、`develop` への PR を作る
4. [AIプログラムレビュー](https://ai.studio/apps/84d224cb-7de1-44fb-995b-9a5917d25603?fullscreenApplet=true) を実行し、指摘があれば直す
5. 進捗ダッシュボードで **PR URL** と **完了日** を記録する

提出課題のない章（環境構築など）は、学習が終わったら **完了日** だけ記録します。

## 5. AI の使い方と質問の仕方

AI は「答えをもらう箱」ではなく、**考える相手** として使います。

- レッスンのコードをそのまま AI に書かせない（自分で打って、動かなかったら聞く）
- エラーは **メッセージ全文** を貼って「原因は何か」「どこを見ればよいか」を聞く
- AI の回答を反映したら、**なぜそれで直ったのか** を自分の言葉でメモする（PR 本文に書く）

各章の末尾に「AIに質問する（この章の例）」を用意してあります。そのまま投げてOKです。

### 質問テンプレ（AI にも先生にも共通）

「エラーが出て直せません」だけでは、答える側に「何をしたいのか」「何が起きたのか」「何を試したのか」が伝わりません。
次のテンプレを埋めてから聞くと、1 回のやり取りで解決しやすくなります。

```md
目的：（最終的に何をしたいか）
現状：（いまのコード／エラー全文／スクショ）
詰まりポイント：（どこで止まっているか）
試したこと：（調べたサイト、検索ワード、試した修正）
自分の仮説：（原因はこれではないか）
確認したいこと：（何が分かれば前に進めるか）
```

全部埋められなくても構いません。最初は「何がエラーメッセージなのか分からない」状態で当然なので、埋められるところだけ書いて質問してください。

フィードバックをもらって直したときは、該当コメントを引用して **どこをどう直したか** を返信してください。
