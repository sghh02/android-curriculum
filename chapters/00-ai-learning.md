# AI時代のAndroid学習法（接続編）

この章は、共通土台「AI時代の思考OSアップデート」を完了した人向けの接続章です。
ここでは、作成済みの日本語設計書を Android 実装に翻訳する進め方を固定します。

---

## 前提

- 「AI時代の思考OSアップデート」を完了している
- `thinking-os-canvas.md`（課題設定キャンバス）がある
- `design-spec.md`（日本語設計書）がある
- `design-change-log.md`（仕様変更履歴）がある
- [コースガイド：6ヶ月でAndroid開発（Compose）を学ぶ](./00-course-guide.md) を読んでいる

## この章の役割

この章では次の1点に絞ります。

- 設計書を、Kotlin / Android / Compose の実装タスクに分解する

この章で新しく「AIの使い方」を覚える必要はありません。
共通土台で身につけた分解・検証・再設計を、Android開発に接続するのが目的です。

## 設計書をAndroid実装へ翻訳する5ステップ

1. `thinking-os-canvas.md` と `design-spec.md` を見て、最優先の機能を1つ選ぶ
2. 機能を Android の責務に分ける
3. AIに「既存コード前提」で実装案を作らせる
4. 差分を `thinking-os-canvas.md` / `design-spec.md` と照合してズレを修正する
5. 仕様変更が出たら `design-change-log.md` に追記する

## 責務分解の目安

| 設計書の記述 | Androidでの主な置き場 |
|---|---|
| 画面要件 | `Composable` |
| 画面状態/入力状態 | `UiState` / `StateFlow` |
| 処理手順 | `ViewModel` |
| データ取得/保存 | `Repository` |
| 例外時の挙動 | `ViewModel` + UI表示 + ログ |

## AIに依頼するときの型

```text
【前提】
共通土台で作成した design-spec.md を実装に落としたい。

【対象機能】
（例）今日の学習タスク一覧表示

【既存コード】
- 画面: ...
- ViewModel: ...
- Repository: ...

【依頼】
既存構成を崩さず、必要な変更ファイルと実装方針を先に提示して。
コードは一気に全部ではなく、手順ごとに提案して。
```

## よくある失敗

- 設計書を読まずに、いきなりコード生成を依頼する
- 正常系だけ実装し、例外時の仕様を落とす
- AI提案をそのまま入れて、`design-spec.md` と不整合になる

## 失敗時の戻り先

詰まったら、共通土台の次を見直してください。

1. Unit 2: 課題設定キャンバスが弱い
2. PHASE 1: 前提や要件の不足
3. PHASE 2: 技術選定理由の不足
4. PHASE 3: 条件分岐の不足
5. PHASE 4: 変更耐性の不足
